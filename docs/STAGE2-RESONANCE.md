# 第二阶段：矿脉共振与连锁采集

这是第二阶段的历史记录。后续五商品方案、增幅上限和最新验收见 [第三阶段](STAGE3-SHOP.md)。

日期：2026-10-16。本阶段只完善共振玩法、对应反馈和验收，不新增商店商品、替换美术或发布代码。

当前工作区在本阶段开始前已有一版共振实现。本轮补充显式 ID 去重、可注入且经过校验的规则配置、不可变采集快照、随载物移动的连接线，以及更严格的边界测试；保留此前未提交的工作。

## 规则与取舍

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `crystalValue` | 120 | 水晶自身的价值 |
| `crystalWeight` | 0.8 | 水晶自身的重量 |
| `radius` | 110 | 水晶中心到矿物中心的连接范围，包含边界 |
| `maxNeighbors` | 2 | 最多连带两件；不包括水晶自身 |

默认规则集中在 `src/core/model.ts` 的 `DEFAULT_RESONANCE`，可通过 `new MinerModel({ radius: 90, maxNeighbors: 1, crystalValue: 100, crystalWeight: 1 })` 创建不同配置。矿物基础属性仍统一放在 `GOODS`。连接范围与矿物碰撞半径是两个不同参数。

配置在创建时复制并冻结。范围和重量必须是有限非负数，数量上限和价值必须是非负安全整数；上限为零时仅回收水晶。配置在失败重试、切关和重新开始后继续有效。

- 普通矿物始终只抓一件；只有直接抓中水晶才查询连带对象。
- 黄金、钻石和石头可参与；水晶不参与其他水晶的连带，不递归传播。
- 候选按距离从近到远排列，同距离按稳定 ID 排序。预览与实际抓取调用同一个查询函数。
- 查询先使用 `Set<string>` 按 ID 去重，再排序和限额。正式关卡按关卡索引与矿物索引生成唯一 ID；异常重复记录以第一条为准，不能重复计价或占据多个名额。
- 抓取时一次性生成冻结的 `CatchBundle`，锁定成员 ID、总价值和总重量，并同时把所有成员标记为 `taken`。回收途中不会再次查询或吸附新矿物。
- 载物回收速度沿用 `420 / (1 + 总重量 × 0.75)`；已有力量效果对整包生效。空钩仍为 600，不新增物理系统或钩爪状态。
- 只有到达绞盘才一次性入账并清空采集包；动画、音效和碰撞事件不负责发钱。

第二关混石矿团的总价值为 $635、总重量 14.1，基础回收速度约 36.3；干净矿团的总价值为 $470、总重量 4.6，基础回收速度约 94.4。高价值混石矿团存在更长的等待和截止损失风险，不能只按总价值选目标。这只是规则数据，不等于人类玩家的最优策略结论。

## 生命周期

| 时刻 | 矿物和采集包 | 收益 |
| --- | --- | --- |
| 出钩前 | 矿物未占用；预览不修改状态 | 无 |
| 抓中 | 全部成员立即占用；生成不可变包 | 无 |
| 回收 | 仅显示该包成员，按整包重量移动；其他水晶不能再连接已占用成员 | 无 |
| 暂停 | 模型、计时和载物反馈冻结；禁止发射和炸药输入 | 无 |
| 回到绞盘 | 矿物保持已取，清空包并切回摆动 | 全包一次性入账 |
| 炸毁 | 整包消失，成员保持已取，消耗一枚炸药，空钩返回 | 无 |
| 超时 | 丢弃未回收包；截止时与回收到达同一步时，截止优先 | 无补发、无部分入账 |
| 失败重试 | 恢复关卡入口钱包与道具，重建全部矿物，清除旧包和事件 | 恢复入口状态 |
| 返回首页或重开 | 清除旧包、事件与视觉反馈，重建矿物 | 不结算旧包 |

## 模块职责

- `src/core/model.ts`：配置、范围查询、去重、采集快照、碰撞后占用、重量回收与结算。保留 `swinging / extending / returning` 三态。
- `src/main.ts`：使用模型配置绘制范围；使用同一预览结果绘制连接、件数、收益和轻重提示；抓取粒子与收拢反馈、多个矿物共同回收、载物连接线。整包成员按图片宽度排列，避免相互遮挡。所有反馈只消费规则结果。
- `tests/model.test.ts`：规则边界、真实运动与单次结算验证。
- `tests/browser/game.spec.mjs`：生产构建上的输入、暂停、炸毁、重试、返回首页和普通抓取回归。

场景中的载物连接线每帧按当前采集包重绘；采集包被清空时随之清除。切关、重试和返回首页继续复用现有反馈清理入口。没有引入事件总线、通用技能框架或物理约束。

## 验收

执行入口：`npm run build`、`npm run test:browser`。浏览器测试使用隔离的 Edge，并对长流程使用虚拟时钟加速；通过正常按钮和键盘输入操作，不直接设置钱包或载物。测试读取只读 QA 快照进行精确瞄准，不能据此报告人类通过率。

规则测试已通过 **34/34**，比本阶段开始时新增 6 项：配置与非法参数、重复 ID、同深度重包截止风险、抓取快照与重叠水晶、截止边界、普通抓取与回收中重置。已有范围边界、稳定排序、最多三件、不递归、炸毁、暂停、超时、重试、帧率差异与完整三关路线测试继续通过。

生产版本浏览器完整回归 **9/9 通过**（约 4.0 分钟），包括完整三关、共振预览、视觉暂停、单次入账、失败重试、整包炸毁、回收中返回首页、重新开始普通抓取，以及既有输入、加载恢复与手机尺寸检查。

截图复查发现固定间距会让两块黄金重叠，因此改为按图片宽度排列。该显示调整后重新执行类型检查、生产构建、全部 **34 项规则测试**，并对三个受影响的共振浏览器场景复验，**3/3 通过**（59.3 秒）。没有把同一场景的重复执行算成新增场景。
