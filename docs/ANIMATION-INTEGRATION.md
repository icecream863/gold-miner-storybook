# 原六关版＋已确认矿工动画

本轮以“原来那一版加上现在的动画即可”为范围，正式游戏仍是六关 Phaser 入口。独立第一关样片保留用于对应此前迭代，不替代六关、商店、特殊物或最终结算。未提交、推送、部署或自动公开 Session。

## 改动

- `src/main.ts`：移除旧角色图片、线段手臂和重复机器，使用一个透明 CanvasTexture 绘制已经确认的整组角色／机器。只创建一次纹理和图像，切关和重开复用；原矿物和效果对象继续按原生命周期管理。
- `src/approved-miner.ts`：统一 0.72 缩放，将样片导轮 `(550,180)` 对齐原规则支点 `(550,130)`，靴底落在约 `y=145` 的旧木台上。手掌、柄头和关节快照使用同一映射，避免两套坐标。
- 直接复用 `src/sample/art.ts`、`src/sample/motion.ts`，没有再制作另一套相似动作。落柄约 140ms，放绳不持续甩柄，回收按实际绳长摇柄，约 180ms 复位；新的发射可以立即打断复位。普通及减少动态均保留核心动作。
- 输入和场景更新共用 `flushPresentation()`。操作先推进原规则时钟，再同步整帧矿物、钩爪、矿工和反馈，暂停不留下上一帧姿势；动画不参与碰撞、计时、计费或速度计算。
- 原炸药与胜负场景、音效和弹窗保留；不再叠加旧人物的炸药／胜负专用表情动作，以保持用户确认的角色动作一致。
- 测试更新旧渲染器断言，并补充坐标、握柄及真实像素变化检查。关键图片失败改为阻断实际仍加载的黄金，避免测试停用的旧人物资源。
- 样片打包只允许已授权的正式场景入口差异；其他基线仍严格检查。原报告保留，不把入口变化伪报为完全未改。

## 交付检查发现的问题

子路径游戏已实际完成六关。初次交付核对在历史 Session 上失败：早期清单缺少 `jsonlSha256`。现在构建身份从随包 JSONL 计算摘要；有清单声明时还会校验声明一致，缺失或下载改变不能静默通过。旧记录内容与清单保持原样，没有伪造早期摘要。

另补两处历史记录页的空图标声明，避免浏览器请求不存在的根目录 favicon；不改变记录正文。第二次核对发现验收脚本硬编码搜索“手柄”，而早期记录没有这个新词，现从实际正文选择搜索词并校验准确结果数量。两次失败日志及报告保存在 `verification/integrated-delivery-first.*`、`integrated-delivery-second.*`，不删掉失败历史。这些是交付工具修正，不改变游戏规则或声音。

## 运行与复测

```bash
npm run build
npm run preview
npm run test:browser
```

浏览器打开 http://127.0.0.1:4173/ 。`?qa=1` 只提供只读观察快照，普通游戏不需要它。正常速度录像使用原六关入口、实际按键和只读状态辅助瞄准，不修改钱包、地图或时间，不代表人类试玩。

PowerShell 单独记录本轮完整六关及真实游戏声音：

```powershell
$env:RECORDING_NAME='integrated'
npm run demo:record
```

音乐和音效沿用原 1.3 设置及存储偏好，本轮没有替换声音。独立样片的音乐默认关闭只属于样片，不强行覆盖完整版本已保存的选择。
