# 按实际实现讲清楚这个项目

以下内容是源码对应的讲解提纲。请自己运行并阅读关键函数后再使用，不要把 agent 的自动化检查说成自己已经做过的人工试玩。

## 为什么使用 TypeScript + Phaser

交付要求是浏览器运行和两天完成。Phaser 提供显示、资源加载、缩放和输入；TypeScript 帮助约束钩爪、关卡和物品的状态。核心玩法保留在独立模型里，便于不启动浏览器也能检查计分与状态转换。Vite 只负责开发和构建，最终是静态文件，不需要后端。

版本不是盲目选择最新版：可行性检查发现 Phaser 官方模板已转向 4，历史模板的分包配置又与 Vite 8 不兼容。实际验证后固定 Phaser 3.90、TypeScript 5.9.3、Vite 8.3.4，并使用精简构建配置。

## 钩爪如何移动和抓取

看 [model.ts](../src/core/model.ts) 中 `step`、`tip` 和 `sweepCircle`。

钩尖位置由固定绞盘点、角度和绳长计算。空闲时角度在左右限位之间反射摆动，出钩后锁定角度、增加绳长，抓到物品或触及边界后回收。回收速度取决于重量，力量药水只影响载物回收。

碰撞使用上一位置到当前位置的线段与扩大后的物品圆求交，取接触参数 t 最小的物品。仅检查当前帧的钩尖点可能漏掉高速越过的小钻石；比较数组顺序也可能抓到后面的物品。

## 如何避免重复抓取和重复发钱

只有 `playing + swinging` 接受发射。抓住物品立即标记 `taken`，后续扫掠跳过它。金钱只在回收到绞盘时修改；飘字、音效和粒子读取已经发生的事件，不承担发钱责任。到期先进入结算状态，挂在绳上的物品清除，后续更新不会继续发钱。

## 暂停、重试和跨关有什么区别

暂停保留当前状态并停止模型更新；隐藏页面和失焦会触发暂停，回来后主动继续。失败重试从本关入口快照恢复，包括进入本关时的余额、炸药和药水。新一局重新初始化整个 run。商店扣除累计余额，力量药水只在紧接着的一关有效。

## 如何检查 AI 的结果

可以讲两个本次真实问题：

1. 构建配置的版本不兼容，通过官方样例和实际打包发现并调整。
2. 手机布局中，最小高度与宽高比共同撑大了容器，导致按钮虽然在 DOM 中但被裁切。通过读取实际边界和截图定位，固定容器宽度后重新通过检查。

还有一次测试定位失败来自按钮包含箭头而脚本使用严格文字匹配，应明确归为测试脚本问题，不说成修复了不存在的玩法 bug。

## 交付与证据边界

目前有 16 项模型检查、17 项基础浏览器断言、14 项整局断言，以及 79.1 秒的正常速度操作录像。三关浏览器检查通过正常键盘输入游玩，不是直接设置金钱或关卡。

这些结果证明检查过的流程能工作，不代表所有设备都兼容，也不能证明所有玩家都觉得手感好。真实手机、Safari、微信和不同网络环境尚未全面验证。正式提交前，应自己完整玩一局，再说明自己的体验与调整建议。
