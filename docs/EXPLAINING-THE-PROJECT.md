# 项目讲解与面试准备（经典六关版）

当前实现为1.3.0经典六关适配与动画声音打磨，旧共振设计已移除，不能在面试中说仍有连锁采集。本页以当前源码为准，阶段2～7报告保留历史过程。

## 一分钟介绍

我用TypeScript和Phaser复刻黄金矿工的核心循环，并做成六关可结束的浏览器小游戏。规则层负责摆钩、碰撞、按重量回收、累计金额和商店；场景只负责输入与表现。后续根据经典复刻目标删掉了共振机制，加入问号袋、移动鼹鼠、TNT和经典五种商店商品。重点处理了移动目标的首次接触、只在回收完成后结算、强化生命周期，以及矿工手掌和手柄脱节。项目有规则测试、六关经济路线和实际生产浏览器验证，AI协作和失败过程保留在Session中。

## 关键调用链

输入 → 推进单调活动时间 → 模型接受launch → 锁定角度伸钩 → 钩尖相对目标运动扫掠 → 按最早接触决定单件快照 → 依重量returning → 到达绞盘产生bank → HUD与音效读取事件。暂停不累计活动时间；截止先清理未回收物，不由动画回调补发钱。

抓取快照包含ID、类型、价值、重量、接触偏移。快照冻结后矿物taken，移动物不再自主往返，回收不会重新碰撞。这样防止重复抓取、抓中后位置跳变和重复入账。不是网络权威/防作弊系统。

动物与钩尖都在移动，不能只用目标帧末位置对钩尖路径判定。每个规则切片保存目标前后位置，将二者位移转为相对线段，做圆碰撞扫掠，比较最小接触时刻。采用1/120秒内部切片，测试30/60/144Hz与长帧。碰撞体为近似圆，非逐像素形状。

TNT用队列传播相邻爆炸，ID集合防止重复处理或死循环，处理规模受当关物品数限制。范围销毁和背包炸药都不发钱，但前者不消耗库存。袋子和本店报价进入关卡/商店时一次生成，种子可复现，帧更新不抽取。

购买时用同一个ShopOffer校验报价、余额、限购和阶段，然后同步扣款并授予库存或下一关强化。强化在下一关构建物品数值、袋子内容与回收速度时实际执行，关末清理；炸药余量跨关，整局重开全清。消费始终影响钱包和下一目标差额。

矿工的手掌和手柄原来由两套坐标驱动。现在共用一个柄头控制点，并使用已确认的连续矢量角色；出钩约140ms落柄，出绳阶段保持低手位，回收时按实际收绳距离摇柄，约180ms回到待机。正式六关场景通过同一0.72缩放映射所有关节与可见导轮，脚底固定，导轮对齐模型支点。规则不依赖人物动画，暂停和重开同步清理姿态。

## 可以说与不能说

可以说：最终动画整合候选58项单元/规则测试、14项生产浏览器场景通过；12条含两次空钩分关路线、9条不同种子和购物策略的全流程路线通过；浏览器检测握柄误差小于2像素。发布候选另有构建及CI冒烟，具体日志分开记录，不把重复运行相加当作更多测试。

不能说：测试通关率代表普通玩家通过率；与商业原版数值完全相同；模型测试证明Safari、真机和人耳听感；把本地地址当作公网地址。正常速度UI试玩、只读瞄准脚本、虚拟时钟测试和提交者本人试玩应分别说明。

完整证据与边界见 [经典版验收](CLASSIC-REMAKE.md)，最终公开提交以 [交付状态](SUBMISSION.md) 为准。

## 1.3.0表现层讲解

规则源码和商店配置未变。最终矿工直接复用已确认样片的矢量轮廓和动作计算，正式场景只做统一坐标映射与绘制；卷筒跟随实际绳长，出绳不连续甩柄。动作只消费事件与快照，不改变输入和入账；输入后整帧同步表现，暂停统一冻结视觉时钟。旧0.18减速和额外胜负表情属于上一轮已停用的人物方案。

背景音乐不是原创，是CC0的Spaghetti Western；界面与采样音效来自Kenney CC0，专用矿工和图标是项目SVG。资源本地随包。首次交互解锁，音乐异步加载与OGG/MP3回退、错误重试解耦；阶段与页面可见性决定是否播放，单源保留偏移，音效限16声部。不能把自动音频计数当作听感通过。
