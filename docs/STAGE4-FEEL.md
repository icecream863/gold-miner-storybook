# 第四阶段：核心手感与交互反馈

本阶段只处理钩爪与载物表现、音效、反馈生命周期和测试。未进入第五阶段美术重构，也未调整价格、布局或经济。

## 检查结论与修改前后的差异

| 项目 | 修改前的实际证据 | 本轮处理 |
| --- | --- | --- |
| 重新开始的角色位置 | 正常速度 UI 试玩复现矿工跑到左侧；自动回归测得重开后 x≈306.97，偏离绞盘位置 | 清空全部视觉起点；后坐力严格限制在 0–1，回归检查角色恢复到绞盘旁 |
| 钩爪轨迹、碰撞与重量 | 已有三态、扫掠检测、按总重量回收及只入账一次的实现和测试 | 保留规则实现，不用动画改变出钩角度、速度或判定 |
| 绞盘与重量表现 | 摇柄固定随时间匀速转动，轻重物体缺乏对应节奏 | 摇柄按实际放绳、收绳距离转动；重载矿工轻微前倾，货物摆动幅度和频率随重量区别 |
| 共振吸附 | 已有连线、整包与共同回收，但全部同时收拢 | 保留即时整包占用，表现增加每件 25ms 的短暂先后；增加短暂命中光环和抓钳高亮，减少普通碎粒数量 |
| 空钩返回 | 没有独立的回收完成提示 | 短暂显示“空钩已回”，配轻量就绪提示音；不产生抓取事件或收益 |
| 收益反馈 | 已有得分飘字，没有对应钱包强化反馈 | 保留准确金额与件数，增加轻微钱包脉冲和三枚短暂金币点；只有模型回收到达才能触发 |
| 暂停与时间 | 模型采用活动时钟，粒子补间与镜头震动仍由引擎时间驱动；原暂停只暂停补间 | 短暂表现全部按活动秒数取样；暂停固定吸附、飘字、镜头和角色姿态，恢复后继续 |
| 音效 | 已有发射、命中、金币、购买及胜负音；缺少持续回收节律，最终通关与普通过关相同 | 增加低音量绞盘节律、空钩就绪音和独立最终通关乐句；保留原事件音 |

摆动仍按原角速度和端点反射运行。本阶段没有足够证据证明需要改变这一规则，也没有用视觉偏移伪装钩尖的碰撞位置。

## 实现与生命周期

`presentation.ts` 仅提供活动时间进度、有限脉冲、轻震和货物姿态计算。它不读写模型、不负责捕获或计分。

场景使用最多 **40 个**短暂表现对象，每个记录开始时刻、寿命与显示目标。每帧按活动时间更新，到期删除并销毁；达到上限先销毁最旧对象。暂停不推进活动秒数，长帧则直接前进到正确寿命，不依赖平滑帧时间慢慢补播。关末、切关、重试和回首页清空全部短暂对象、捕获起点、视觉时间戳及镜头偏移。

长帧中若抓取已经完成并入账，场景不会倒放过期的吸附和命中音。规则事件仍由模型产生，表现完成时没有发钱或改变矿物状态的回调。

镜头仅在炸药使用时轻震，最多约 1.6 世界像素、持续 120ms；无常规命中震动。低动态偏好关闭镜头偏移、货物摇晃与钱包缩放，减少颗粒，并立即完成吸附定位。

绞盘音根据载物情况降低音高、放慢节律，避免长时间高音重复。音频在用户操作后创建或恢复 `AudioContext`；构造或恢复被拒绝时保留正常玩法。所有声部结束后断开节点，静音、暂停和场景清理即时停止声部，上限 **16 个**；关闭的音频上下文可以在后续用户操作中重建。音效合成器仍无外部音频依赖。

所有新图形对象都不设置交互区域；鼠标、键盘和触屏继续走现有输入入口。

## 真实 UI 试玩与证据边界

使用本地生产预览，在可见浏览器中通过按钮和按键正常速度试玩，没有读取瞄准状态、安装虚拟时钟或改写金钱。

- 修改前：正常出钩后回首页重开，观察到矿工明显向左偏移。
- 修改后：实际抓取小金块 $100、金块 $250、大金块 $500，第一关结算为 $850。
- 从商店实际购买力量 $150、增幅 $180，余额由 $850 降至 $520；进入第二关显示两种强化。
- 抓到含石头的三件共振包，显示 $635 与约 4.8 秒重载回收；回收期间持续按键没有再次发射。到达后钱包为 $1155，本关采集 $635，随后暂停。

这是 Agent 的正常速度交互观察，**没有完成三关人类手感评审**。完整三关通过由下述自动化证明；不能把两种证据混为一谈。工具没有提供人耳听感，因此只验证音频解锁、生成和清理，音量与听感仍需本人确认。

## 修改文件

- `src/main.ts`：清理时间戳、命中与回收表现、统一短暂对象更新、轻震、钱包脉冲、就绪提示、只读验收字段。
- `src/presentation.ts`：独立、无规则副作用的表现时间与姿态函数。
- `src/audio.ts`：绞盘、就绪与最终通关音，声部预算和上下文恢复。
- `tests/presentation.test.ts`、`tests/audio.test.ts`：帧率取样、未来时间戳、低动态、声音类型、1000 次快速调用预算与清理、禁用或拒绝音频。
- `tests/browser/feel.spec.mjs`：重开位置、吸附、重载、飘字、轻震、暂停、长帧、降级、静音、空钩与桌面短样本。
- `scripts/browser-playthrough.mjs`：完整三关同时记录表现对象和声部峰值。

本阶段开始时保存了 `core/model.ts` 和 `core/shop.ts` 的 SHA-256，修改后逐文件比对均一致；七条模型路线的金额、采集额和空钩数量与第三阶段相同。

## 自动化验收

类型检查、生产构建和 **53/53 单元及规则测试通过**。原有规则与商品测试全部保留，新加五项表现与音频测试。

重开回归在修改前实际失败，见 [stage4-baseline.log](verification/stage4-baseline.log)。修复后首批五个专项场景 **5/5 通过**，见 [stage4-feel.log](verification/stage4-feel.log)。单元测试首轮有一次浮点数严格相等断言失败（差约 10^-15）；改为正确的浮点比较，未修改表现参数来迎合该断言，原始输出保留在 `stage4-build-first-attempt.log`。

完整生产浏览器回归首轮 **15/16 通过**。唯一失败发生在空钩用例发射前：50ms 采样可能跨过过窄的端点角度窗口。将测试瞄准窗口放宽为地图上确实没有矿物的右侧角度区间后，空钩专项通过，确认返回就绪文字和声音、零收益、矿物状态未变。该修正没有修改运动速度、矿物布局或碰撞。

空钩与新增桌面短样本合计 **2/2 通过**；本阶段所有 **17 个不同浏览器场景均取得通过结果**，这是分批验证，未声称一次运行 17/17 全绿。原有完整三关、五道具与下一关效果、暂停、重试、重新开始、资源加载恢复、键鼠输入和原生触屏回归均通过。

- [完整回归首轮原始输出](verification/stage4-browser-first-attempt.log)：15 通过及采样失败；`stage4-browser-final.log` 是同一次运行的原始文件名，内容包含该失败。
- [修正后的空钩与短样本](verification/stage4-followup.log)：2/2。
- [区分浏览器调度与场景更新的短样本](verification/stage4-frame-sample.log)：后续仅重跑新增的性能采样，1/1。

最新桌面样本包含 179 个浏览器帧调度间隔：平均约 5.75ms、95 分位约 8.6ms。同期观察到 180 次场景更新，平均间隔约 6.55ms、95 分位约 8.8ms，短时反馈对象峰值 7、音频声部峰值 5。样本仅约一秒、只覆盖一次普通抓取，不是长期游戏帧率或重载场景压力测试，也不能与旧报告中的不同环境直接比较。
